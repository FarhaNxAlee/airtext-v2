## 2. Hover, Focus & Theme System Fixes (`client/style.css` & `src/html.ts`)

### 2.1 Remove Destructive `!important` Overrides Blocking Hover & Focus
- **Issue**: `client/style.css` (lines 104–106) contains legacy global overrides:
  ```css
  .bg-violet-500, .bg-violet-600 { background: var(--accent) !important; color: var(--accent-text) !important; }
  .text-violet-300, .text-violet-400, .text-cyan-300 { color: var(--accent) !important; }
  .border-white\/5, .border-white\/10 { border-color: var(--line) !important; }
  ```
  1. `.border-white\/10 { border-color: var(--line) !important; }` **completely blocks** every `hover:border-*` and `focus:border-*` utility on any element that also has `border-white/10` (affecting almost all inputs, selects, and secondary modal buttons in `src/html.ts`).
  2. `.bg-violet-500 { background: var(--accent) !important; }` **completely blocks** `hover:bg-violet-400` on the `Unlock`, `Copy link`, and `Download` buttons.
  3. Elements without `.border-white/10` that use `hover:border-violet-400/40` or `hover:bg-violet-500/10` flash **purple** on hover against a **lime (`#c9f31d`)** brand theme.
- **Fix**:
  - Replace hardcoded `violet-*`, `cyan-*`, and `border-white/10` classes in `src/html.ts` and `client/main.js` with theme-aware semantic classes (`.btn-secondary`, `.input-field`, `.card-interactive`) backed by CSS variables (`var(--line)`, `var(--accent)`, `var(--accent-strong)`, `var(--accent-soft)`).
  - Remove `!important` from `.border-white\/10` and `.bg-violet-500` so hover and focus transitions work smoothly in both Dark and Light mode.
  - Update toast notifications (`client/main.js`, lines 4823–4828) from purple (`#242033` / `bg-violet-400`) to match `var(--panel)` + `var(--accent)` border/dot.

### 2.2 Fix `.note-row:hover` vs `.tier-card-admin` & Non-Clickable Rows
- **Issue 1 (Admin Gold Card Hover Bug)**: `.tier-card-admin` (`client/style.css`, lines 434–448) draws its gold gradient border using a 2-layer `background` (`padding-box` + `border-box`) and `border: 1px solid transparent`. However, `.note-row:hover` (`client/style.css`, line 219) sets `background: var(--accent-soft); border-color: var(--accent);`, which wipes out the gold gradient border on hover and flashes the card neon green.
- **Issue 2 (Non-Clickable Row Hover in Screenshot 2)**: `.note-row:hover` turns the entire row olive-green (`var(--accent-soft)`) even though clicking the row body does nothing, while the buttons inside `.note-actions` have no `:hover` rules at all.
- **Fix**:
  - Change `.note-row:hover` to a subtle elevation + surface shift (`border-color: color-mix(in srgb, var(--accent) 45%, var(--line)); background: color-mix(in srgb, var(--panel) 85%, var(--accent-soft));`) rather than flooding the card with green.
  - Add an explicit `.note-row.tier-card-admin:hover` rule that preserves the 2-layer gold `border-box` gradient and slightly intensifies `--tier-admin-glow` on hover.
  - Give all buttons inside `.note-actions` and `.admin-row-actions` crisp hover feedback (`hover:border-[var(--accent)] hover:bg-[var(--accent-soft)] hover:text-[var(--text)]`, and red fill on `Delete` hover).

## 3. Responsive & Multi-Device Layout Fixes

### 3.1 Prevent Action Bar Overflow on Mobile & Tablet (`320px` – `900px`)
- **Issue**:
  - `.note-actions` (`client/style.css`, line 225) and `.admin-row-actions` (line 575) use `display: flex` without `flex-wrap: wrap`.
  - On `/account`, rows have 5–6 buttons (`Open`, `Copy link`, `QR`, `Edit`, `Share to Wi-Fi`, `Delete`). Between `641px` and `860px`, `.note-row` uses `grid-template-columns: minmax(0,1fr) auto`, squeezing the title column; below `480px`, the unwrapped buttons overflow horizontally.
- **Fix**:
  - Add `flex-wrap: wrap` to `.note-actions` and `.admin-row-actions`.
  - Switch `.note-row` to single-column stacked layout at `@media (max-width: 768px)` (instead of `640px`) whenever it contains 4+ action buttons, with full-width or evenly gridded touch targets (`min-height: 38px`) on mobile.

### 3.2 Fix Mobile Bottom Bar Leaking onto `/admin`
- **Issue**: `MOBILE_BOTTOM_BAR` (`src/html.ts`, line 1694) is outside `<div id="public-app">`. On `/admin`, `#public-app` is hidden via `.hidden-force`, but `MOBILE_BOTTOM_BAR` stays visible on screens `<= 900px`, overlapping the Admin Panel.
- **Fix**: Move `MOBILE_BOTTOM_BAR` inside `<div id="public-app">` (or hide it when `APP.initialAdmin` is true).

### 3.3 Improve Admin Sidebar on Mobile (`<= 900px`)
- **Issue**: At `@media (max-width: 900px)` (`client/style.css`, lines 587–590), `.admin-sidebar` becomes a horizontal scrolling strip containing the brand logo, 5 tabs, and the D1/R2 health dots all in one row, which cramps on phone screens.
- **Fix**: Stack `.admin-sidebar-brand` + health indicators in a compact top row on mobile, with `.admin-sidebar-nav` as a full-width horizontally scrollable pill bar underneath.

### 3.4 Restore Expiry Selector on Homepage Quick-Share Card
- **Issue**: `#quick-share-card select[id$="-ttl-select"] { display: none; }` (`client/style.css`, line 161) hides the expiry dropdown on the homepage, so users creating a drop from `/` cannot pick an expiry duration.
- **Fix**: Keep the expiry `<select>` visible in `#quick-share-card` with compact styling so homepage drops have full feature parity with `/text` and `/files`.

## 4. Dynamic Behavior & Logic Bug Fixes

### 4.1 Fix `init()` Early Return Breaking `/account` & `/admin` (`client/main.js`)
- **Issue**: In `client/main.js` (lines 42–55), `init()` returns early on `APP.initialAdmin` and `APP.initialAccount` before running:
  - `applyPublicSettings()` (leaving `#footer-year`, social links, developer name, and announcement bar uninitialized on `/account`).
  - `window.setInterval(updateCountdowns, 1000)` (so live expiry countdowns never tick on `/account` or `/admin`).
  - `syncWebShareButtonVisibility()` (so the native mobile `Share…` button in `#qr-modal` stays hidden on `/account`).
  - Additionally, `renderAccountNotes()` (line 2667) and `renderAccountFiles()` (line 2752) omit `expiry.setAttribute("data-expires", String(expiresAt))`.
- **Fix**:
  - Run `applyPublicSettings()`, `syncWebShareButtonVisibility()`, and the 1-second `updateCountdowns` interval across all routes.
  - Add `data-expires` attributes to `.note-expiry` nodes in `renderAccountNotes()` and `renderAccountFiles()`.

### 4.2 Fix Live Polling & Auto-Expiry for Nearby Files (`client/main.js`)
- **Issue**:
  - `startPolling()` (`client/main.js`, lines 4490–4495) only polls `loadLocalItems(false)` every 10 seconds and never calls `loadLocalFiles(false)`.
  - `updateCountdowns()` (lines 4504–4506) prunes expired items from `state.items` and re-renders `renderLocalItems()`, but never prunes expired `state.files` or re-renders `renderFilesBoard()`.
- **Fix**:
  - Poll both `loadLocalItems(false)` and `loadLocalFiles(false)` in `startPolling()` (only when `#board-list` or `#files-board-list` is present on the page).
  - Prune expired `state.files` in `updateCountdowns()` and call `renderFilesBoard()` when the count changes.

### 4.3 Fix `Escape` Key Handling for Edit Modals (`client/main.js`)
- **Issue**: The `Escape` key handler (`client/main.js`, lines 689–696) does not check `el.editItemModal` or `el.editFileModal`. Pressing `Esc` while editing a drop from inside `#item-modal` closes `#item-modal` in the background while leaving `#edit-item-modal` stuck open.
- **Fix**: Check `el.editItemModal` and `el.editFileModal` **first** in the `Escape` key priority chain before `el.fileModal` and `el.itemModal`.

### 4.4 Fix "Open Once" (`burnAfterRead`) Security & Logic Bug (`src/routes/notes.ts` & `src/routes/files.ts`)
- **Issue**:
  1. When a user creates a note or file with **Open once** (`burnAfterRead: true`), `POST /api/items` (`src/routes/notes.ts`, lines 453–457) and `POST /api/files` (`src/routes/files.ts`, lines 670–674) still insert it into `network_notes` / `network_files`, broadcasting it onto the public Wi-Fi Nearby board.
  2. Even worse, `GET /api/local/item/:itemId` (`src/routes/notes.ts`, lines 476–493) and `POST /api/local/item/:itemId/unlock` (lines 495–514) **never delete/burn the note when opened from the Nearby board** — meaning anyone on the Wi-Fi can read an "Open once" note unlimited times!
  3. Meanwhile, `POST /api/me/shares/notes/:noteId/share-to-network` (`src/routes/me.ts`, line 263) explicitly blocks sharing "Open once" drops to a network board (`409 BURN_AFTER_READ_NOT_SHAREABLE`).
- **Fix**:
  - Do **not** insert `burn_after_read = 1` notes or file groups into `network_notes` / `network_files` on creation (or if edited to `burnAfterRead: true` in `applyNoteEdit` / `applyFileGroupEdit`, remove them from `network_notes` / `network_files`), keeping "Open once" drops strictly accessible via their direct code/link/QR.
  - Also include `burnAfterRead: wantsBurnAfterRead` in the `POST /api/items` response payload (`src/routes/notes.ts`, line 465).

### 4.5 Fix Per-Viewer `Mine` vs `Shared on Wi-Fi` Badge Logic
- **Issue**: `network_notes.source` (`'mine'` | `'received'`) is stored per-Wi-Fi-room in D1 rather than per-user/browser. As a result:
  - A stranger on the same Wi-Fi sees `MINE` on a drop created by someone else on that Wi-Fi.
  - Conversely, when a signed-in user re-shares their own drop from another network or views it logged out (as in Screenshot 1), it can show `RECEIVED` next to their own name badge.
- **Fix**:
  - Compute ownership per viewer: a drop is **`Mine`** if `getDeleteToken(id)` exists in `localStorage` OR if the logged-in session user's `id` matches `note.user_id` / `group.user_id`. Otherwise, badge it as **`Nearby`** (or **`Received`** if opened via code/link).

### 4.6 Project `burn_after_read` in Admin Drops API (`src/routes/admin.ts`)
- **Issue**: Flagged in `CLAUDE.md` line 233: `GET /api/admin/drops` filters by `burn_after_read`, but omits `burn_after_read` from its `SELECT` projection, so the `Open once` badge only renders in `/admin` when the "Open once" filter is active.
- **Fix**: Include `burn_after_read` in the `SELECT` union in `src/routes/admin.ts` and render the `Open once` badge unconditionally in `renderAdminDrops()`.

## 5. Unique Features & Functional Upgrades (Making AirText Stand Out)

### 5.1 Unified "Live Wi-Fi Radar" on `/nearby`
- **Concept**: Instead of two disconnected, asymmetric boxes ("Text" and "Files") on `/nearby`, present a unified **Nearby Radar** experience:
  - **Top Radar Strip**: Animated pulsing Wi-Fi radar indicator showing `Live on this Wi-Fi · Auto-syncing` + total active drops count + `Share Text` / `Share Files` quick buttons.
  - **Unified Filter & Search Bar**: One search box (`Search nearby drops by title or code…`) and instant filter pills: **`All`**, **`Text`**, **`Files`**, **`Mine`**, **`Open`**, **`PIN Locked`**.
  - **Quick Copy / Quick Download from Row**: For unlocked text drops on Nearby, add a 1-click **`Copy`** button right next to `Open` so users don't even have to open the modal just to copy a snippet or link.

### 5.2 "Your Active Drops" Session Tray for Anonymous Users
- **Concept**: Anonymous users already have `airtext_owner_tokens` saved in `localStorage`. Right now, if an anonymous user creates a drop on `/text` or `/files` (especially an **Open once** drop that isn't listed on Nearby) and closes the QR modal, they have no way to find, edit, or delete it again.
- **Feature**:
  - Render a collapsible **"Your recent drops on this browser"** tray below the form on `/text`, `/files`, and `/` (powered by `airtext_owner_tokens`).
  - Allows anonymous creators to **Open**, **Copy Link**, **Show QR**, **Edit in place**, or **Delete** their active drops at any time before expiry.

### 5.3 Smart Content Detection & One-Click Actions in View Modal (`#item-modal`)
- **Concept**: Make opening a text drop intelligent by detecting the content pattern client-side in `showItemResponse()`:
  - **Single URL Detected**: Display a prominent **`Open Link ↗`** primary action button and an inline mini-QR code right inside the view modal.
  - **Code / JSON / Env / Config Detected**: Offer a **`Format JSON`** / **`Monospace + Line Numbers`** toggle and a **`Download as File (.txt / .json)`** button.
  - **OTP / Verification Code Detected**: If the text contains a 4–8 digit verification code, surface a **`Copy Code (123456)`** one-tap chip at the top of the modal.

### 5.4 Rich Media Previews, Upload Progress Bar & "Download All" (`#file-modal` & `/files`)
- **Upload Progress Bar**:
  - Replace `fetch()` in `createFileShare()` with an `XMLHttpRequest` upload progress listener so uploading multi-megabyte files shows a real-time percentage bar (`Uploading… 68%`) instead of a static spinner.
- **Inline File Previews in `#file-modal`**:
  - When a file group is unlocked/opened in `renderFileModalList()`, render inline previews for safe media types:
    - **Images (`image/png`, `image/jpeg`, `image/webp`, `image/gif`)**: Clickable thumbnail preview.
    - **Audio / Video (`audio/*`, `video/mp4`, `video/webm`)**: Inline HTML5 player.
    - **Text / Code (`text/plain`, `application/json`, `text/csv`)**: Expandable inline text preview.
- **"Download All" Button**:
  - When a file drop has 2+ files, show a **`Download all (N files)`** button at the top of `#file-modal`.

### 5.5 True Zero-Knowledge Browser Encryption (`allowClientEncryption`)
- **Concept**: The database columns (`body_encrypted`, `encryption_iv` in `notes`) and role limit (`allowClientEncryption`) already exist, and `/account`, `/faq`, and `/privacy` already describe it.
- **Implementation**:
  - When a user with `allowClientEncryption` locks a note with a PIN, derive an AES-GCM-256 key in the browser via `crypto.subtle` (PBKDF2 from the PIN + a random salt), encrypt the note body client-side before `POST /api/items`, and decrypt it client-side on unlock.
  - Display a **`🔒 End-to-End Encrypted`** badge on encrypted notes so users can visually see the zero-knowledge guarantee.

### 5.6 Interactive Auto-Advancing Code Input on `/receive`
- **Concept**: Upgrade `/receive` (`#join-card`):
  - Auto-submit the moment a user pastes a valid 6-character share code or full `/s/CODE` / `/f/CODE` URL into `#join-code` (supporting pasting a full URL and automatically extracting the code!).
  - Add a **"Paste from clipboard"** 1-tap button next to the code input for mobile users.
